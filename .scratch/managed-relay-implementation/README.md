# Managed relay implementation backlog

Published: 2026-09-27
State: implementation in progress; ticket statuses below are authoritative.

This is the separate build backlog for the
[accepted single-process v1 specification](../managed-relay-service/spec.md).
The [resolved Wayfinder map](../managed-relay-service/map.md) and its decision
tickets remain historical decision records; they are not implementation tasks.
This publication changes neither that map nor the specification.

There are **32 initial-delivery tickets and one deferred capacity ticket**.
Every ticket has its own contract, blocking edges, testable acceptance criteria
and demonstration. Source links identify the accepted requirements, not competing
proposals. The specification remains authoritative; report a real discrepancy
rather than silently changing policy or reviving an obsolete design.

## Working the backlog

Read the selected ticket, its cited specification sections, required predecessor
results and the destination repository's current instructions. The per-ticket
**Blocked by** line is the authoritative dependency graph; all blockers must be
resolved before work starts. Record a claim before editing implementation;
append evidence and resolution under Comments, and mark resolved only after the
acceptance checks pass. Update frontier reporting from ticket state rather than
marking the original decision tickets again.

Tickets cut complete observable paths through their necessary persistence,
operations, adapters and UI, with tests in the same slice. Prefactoring stays
behavior-preserving. Later qualification composes those checks and corrects
integration defects; it does not postpone foundational safety to a hardening
phase. Early isolated slices are not permission to serve publicly.

Environment-dependent work requires authorized targets and actual operator
inputs. Missing credentials, devices, runners or infrastructure are recorded
**not run**, never passed. No ticket grants production mutation, infrastructure
provisioning, publication or load against unapproved systems. Build/CI success
does not replace human promotion through manual Argo phases.

[Measure target-scale capacity](issues/33-measure-target-scale-capacity.md) remains **deferred**, excluded from the initial frontier and
initial release gate even when its candidate dependency resolves. Start it only
after separate scheduling and load-environment authorization. The existing
limits and 1,000-account/5,000-session goal remain unchanged and unproven.
